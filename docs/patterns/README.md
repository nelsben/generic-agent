# Pattern index

Customer Summary as a workbook: one page per architecture pattern, each written for the seller or service rep it
serves first and for the builder who takes it. Read them in this order. Each title is the page's own heading, and the
file names do not change. The repo's README and the architecture page copy their pattern lists from this table.

| # | Page | Kind | What it gives a seller or a service rep |
| --- | --- | --- | --- |
| 00 | [Why custom](00-why-custom.md) | chapter | Why the product is Agentforce with its own surfaces and cards, and when the standard chat is enough |
| 01 | [Route, gather, reduce](01-route-gather-reduce.md) | chapter | One summary of an account's deals, service and people, built only from records the rep can see |
| 02 | [Ask anything](02-ask-anything-explorer.md) | chapter | The next question in their own words, answered from the CRM data they can see, with rows to drill into |
| 03 | [Hotkey panel](03-hotkey-panel.md) | chapter | The compact window one key away on any page, so a question never means leaving the record |
| 04 | [Model provider seam](04-model-provider-seam.md) | chapter | Answers from one model door and prompt files a team can tune in minutes, through the trust layer |
| 05 | [Memory and customer history](05-conversation-memory.md) | chapter | Follow-ups that know the last answer, and a customer history every new summary starts from |
| 06 | [Appendix: the Agentforce agent (optional)](06-agent-routing-and-verbatim-relay.md) | appendix | The same skills in the standard Agentforce chat, for a team that wants the registered agent too |
| 07 | [Trust by design](07-trust-access-and-failure.md) | principles page | An assistant that sees only what the rep sees, and one plain sentence when something fails |
| 08 | [Testing an AI feature on Salesforce](08-test-and-release-lifecycle.md) | chapter | Changes that reach them only after a ladder of tests, from Apex to a real browser and the agent |
| 09 | [Outside door (MCP)](09-outside-door-mcp.md) | chapter | The same summary, questions and two writes from an AI client outside Salesforce, signed in as the rep |
| 10 | [Brand and theming](10-brand-and-theming.md) | chapter | An agent that carries the prospect's or customer's own name, logo, colours and tone |
| 11 | [Voice input](11-voice-input.md) | chapter | A question spoken instead of typed, landing in the composer to check before sending |
| 12 | [Right rail](12-right-rail.md) | chapter | A full-height side panel with the conversation, the account's facts, its history and its sentiment |
| 13 | [Write actions](13-write-actions.md) | chapter | A follow-up or an update said in their own words, shown as a draft, and written only on Confirm |
| 14 | [Embedded surface (call centre)](14-embedded-surface.md) | placeholder | Not built: the idea of a service rep briefed on the caller as soon as they accept a call |
